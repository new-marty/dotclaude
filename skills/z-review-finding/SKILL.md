# レビュー指摘の書き方

## 合格ライン

指摘を読むのは、コードを開いていない人である。その場で何も調べられず、一度読んだだけで何かを決めなければならない。

**その読者が、読んだあとに問題を自分の言葉で言い直せること。** これが合格ラインで、ここを外した指摘は、どれだけ正確でも失敗している。

## 四つの手順

問題を起こしている最小の具体例から始め、そのあとに説明を置く。順番を入れ替えない。

1. **正しい姿と、それに対する破れを見せる。**
   動かせるコードなら、コマンドと出力、呼び出しと戻り値、リクエストと応答のいずれかを、期待値を並べて書く — `ParseDuration("500ms") → 0s (期待 500ms)`。
   構造だけを変えていて何も出力されないなら、その変更が壊す場面を平たい言葉で書く。
   条件によって挙動が変わるなら、2つの場合を対比する。破れが明らかになるのは、たいていこの対比である。
2. **かんたんな説明** — 日常の言葉で1〜2文。問題に名前を付けるだけで、原因の連鎖は書かない。読者は詳細に入る前に大筋をつかむ。
3. **何がそれを起こしているか**を、2と同じ言葉で書く。
4. **何を損なうか**を書く。

## 書き方の規則

- **コード上の名前ではなく、物の名前で呼ぶ。** `svc.rc` ではなく「リトライ回数のカウンタ」。識別子と `file:line` は、平たい名詞のうしろに括弧で添える錨である。説明をそこに担わせない。
- **略記は初出で開く。** 要件ID、チケット番号、プロジェクト内の略語は、読者に何も伝えない。
- **観測していないものを書かない。** そのコードパスを今の形で走らせられないなら、構造の差分をコマンド出力のように見せかけず、場面で示す。
- **長さは理解のしやすさに従う。** 埋草は削る。話を着地させるための前置きは削らない。
- **指摘が本物であることを論じない。意図を要約し直さない。** 具体例と説明で足りている。
- **選択肢は空行で区切る。** 1行に畳まない。

## テンプレート

```markdown
### 指摘 n / m — <ID>: <短い題>

分類: <正しさ / セキュリティ / 保守性 など>
場所: <file:line>

<問題を起こしている最小の具体例。コマンドと出力、リクエストと応答、呼び出しと
戻り値のいずれかを、期待値と並べて書く。何も動かないなら、その変更が壊す場面を
書く。説明せず、見せる。>

**かんたんな説明**

<日常の言葉で1〜2文。詳細を読まなくても読者が言い直せるところまで。原因の連鎖も
選択肢も書かない。>

**詳細**

<地の文で続ける。何がそれを起こし、何を損なうか。上の具体例と同じ平たい言葉で。
着地するのに必要なだけ書き、それ以上は書かない。>

**決めること**

<読者に問うている、ただ一つの問い>

**選択肢**

A. <何をするものか、その代償>

B. <選択肢>

**推奨 (B)**

<選んだ記号と、なぜかを一節。場当たりの対処ではなく、長く効く方を選ぶ。>
```

選択肢は、並べることで判断がはっきりする場合にだけ置く。そうでなければ省き、推奨だけを書く。推奨は `A + C` のように組み合わせてもよい。

## 例

```markdown
### 指摘 1 / 1 — M1: ParseDuration が1秒未満の値をゼロに切り捨てる

分類: 正しさ
場所: internal/timeutil/parse.go:42

  ParseDuration("500ms")  → 0s     (期待 500ms)
  ParseDuration("1500ms") → 1s     (期待 1.5s)

**かんたんな説明**

1秒未満の時間指定が黙って切り捨てられるので、500ミリ秒のタイムアウトを渡すと
タイムアウトなしになる。

**詳細**

結果を秒単位で組み立てているため、ミリ秒の端数は時間の値を作る前に落ちている。
1秒未満のタイムアウトを渡した呼び出し側は、タイムアウトが効かない状態になる。
しかも失敗が表に出ない。呼び出しは正しい型の値を返し、ただ中身が違う。

**決めること**

ナノ秒から組み立て直すか、浮動小数点数で持ち回るか。

**選択肢**

A. ナノ秒で組み立ててから変換する — 誤差が出ず、標準ライブラリが同じ文字列を
   解釈するやり方と揃う。

B. 秒はそのままにしてミリ秒のフィールドを足す — 同じ結果を得るのに変更範囲が
   広く、間違えられる箇所が増える。

**推奨 (A)**

ナノ秒を基準にすれば `time.ParseDuration` と挙動が揃い、精度も落ちない。
```

## 出力する言語

指摘は、それを読む人の言語で書く。英語のリポジトリの PR コメントは、日本語で
相談していても英語で書く。テンプレートの見出しも訳す。

| 日本語 | English |
| --- | --- |
| 指摘 n / m | Issue n of m |
| 分類 | Category |
| 場所 | Location |
| かんたんな説明 | Simple Explanation |
| 詳細 | Details |
| 決めること | Decision |
| 選択肢 | Options |
| 推奨 | Recommendation |

合格ラインと四つの手順は言語に依らない。上の例が日本語なのは、この文書が日本語で
書かれているからにすぎない。
