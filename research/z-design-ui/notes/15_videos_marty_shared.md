# Marty が「こういうことの話をしている」と共有した動画

調査日: 2026-10-26。Marty が UI を作れるようになるための知識の例として共有した動画。字幕(英語の自動字幕)を読んでまとめた。字幕の取れなかった動画はその旨を書く。

## 結論

1. 5 本とも「見た目の飾り方」ではなく、配置・大きさ・色・余白の一つひとつを、利用者の意図と内容から説明している。Marty の言う「全てに意味がある」はこの説明の仕方を指す。
2. 共通する考え方は、まず利用者がこの画面で何をしたいかを書き出し、そこから要素を足すこと。装飾は機能を変えないので最後に回す。
3. 判断の言葉は具体的で、どれも検査できる。「最初に見せたいものを一番大きく」「近いものは同じ組に見える」「影を弱めたら、押せる範囲が分かるように薄い線を足す」「ボタンは高さ 44px 以上」。
4. 慣習(上から下、左から右、ナビは上)に従い、外すときは意図して外す。外すのは小さな動きや独自の機能など、一点に絞る。
5. 実データの端の場合(長い名前、明るい画像の上のアイコン)まで先に考える。

## 各動画の要点

### How to think like a GENIUS UI/UX designer(Kole Jain、2025-06-27、5:31)
https://youtu.be/HE4rLEQpiXY

- 見た目を良くすることより、利用者のために機能させることを先に考える。Web デザインは芸術ではなく物語で、目的が行動へ導くことなら、派手な演出は邪魔になりうる。
- 利用者の意図から始める。宿を探す人の意図は「探す」なので、検索欄が出発点になり、行き先・人数・日付を足す。背景に画像を敷く見出しを足しても、機能は何も増えない。
- 意図は複数ありうる。行き先が決まっていない人は眺めたいので、一覧を見せ、絞り込みを足す。書体・色・アイコンは見た目を変えるが、機能はほとんど変えない。意図が広がったときだけ機能を広げる。
- 30 年分の慣習があるので、情報は上から下、左から右に流し、ナビは上、行動を促すボタンは目立たせる。慣習に従うと、新しい区画を足しやすく、レスポンシブにもしやすい。慣習を守りつつ、小さな動きや独自の機能で自分らしさを出すのが「天才」との差。
- 内容の設計は二段。何を表示するかを決める(一覧では説明文を省き、場所・評価・価格だけ。詳しくは詳細で見る)。次に、表示する内容の端を決める(長い名前は切り詰める、明るい画像の上の保存アイコンには円を敷いてコントラストを保証する)。
- 動きは明快さか機能を足すときだけ使う。リンクが増えてメニューに畳むときの出現、閲覧が主になったら検索欄を小さくして押したら開く、など。いずれも段階的開示。無限スクロールより「もっと見る」が良い。利用者が制御でき、フッターに届くから。ボタンにはほぼ必ず小さな動きを付け、スクロールを乗っ取る演出はほぼ使わない。
- デザインシステムはチームの価値観を映す。小さなスタートアップには軽くて捨てやすいもの、Material のように数十の製品と数十億人を相手にするなら巨大で厳密なもの。作る過程(余白、文字の階段、操作の型を決めること)が、拡張の骨組みになる。目的は全部を同じに見せることではなく、共通の言葉を持つこと。規則は事故で破らず、意図して破る。

### Improve your UI designs with these 4 steps(Jonathan Waterworth、2025-05-30、1:58)
https://youtube.com/shorts/S2JbPNiuPE4

1. 色を減らす。悪い黄色の背景は白に、ほかの色も減らせるか一つずつ見る。
2. 書体をそろえる。4 書体は多すぎるので 1 つに。そのうえで階層を直す。利用者に最初に見せたいものを一番大きくし、そこから下げる(見出し → 本文 → 著者情報)。
3. 余白と組み分け。カード周りの余白を広げて息をさせる。近さで組を作る(画像、見出しと説明、著者と日付)。組にすると拾い読みしやすい。
4. 控えめにする(一番難しい)。強すぎる影を弱める。弱めると押せる範囲が分からなくなるので、薄い線を足す。角が鋭いので少し丸める。悪目立ちするボタンは、すっきりした文字と矢印にする。

### Level up your UI design skills in 7 minutes! EP1(Rachel How、2023-06-01、7:12)
https://youtu.be/MoVO8eVe3gI

- リデザインは全部を変えることではない。うまくいっている部分とブランドの識別性を残す。
- 何かを描く前に、この画面で利用者がすること(支払い方法を選ぶ → 住所 → 注文を確認。確認が済むまで課金されない)を書き出す。
- 批評の観点の例: 見出しが次に何をすべきかを伝えていない、戻るボタンがない、ステッパーで現在の段がはっきりしない、青地に白い文字はコントラストが足りない、ボタンは高さ 44px 以上、3 つのアイコンの不統一、ラジオボタンが小さく非選択の状態が分かりにくい、「カードを保存」が無い、有効期限と CVV が切れて見える、ボタンは「追加」ではなく「カードを追加」と具体的に。
- 良い点の例: 浮いた青いカードには、その色に合う青い影を付けている。
- 進め方: 何年やっていても実在の製品を参照して型を学ぶ。薄い淡色の背景は目に優しくコントラストも出る。ステッパーの各段に副題を付け、未到達の段は不透明度を下げ、現在の段を太字に。カードは実物の比率(クレジットカードの縦横比)に合わせる。追加はカルーセルの末尾に置くと流れが良い。ロゴは目で見て大きさをそろえ、右に揃える。「まだ課金されません」と小さく書いて安心させる。カード番号の読み取り、CVV の場所のヘルプを足す。
- 目標: 決済は速く直感的で、利用者がすぐ払って去れること。

### 4 Foundational UI Design Principles: C.R.A.P.(Jesse Showalter、2022-04-13、9:15)
https://youtu.be/uwNClNmekGU

- Contrast(対比): 階層を作り、焦点を強調し、視覚的な面白さを出す。色・太さ・大きさ・画像で作る。例: 見出しを 24 → 54px、medium → semibold に上げて本文との対比を作り、主題(自転車)を大きくして焦点にする。
- Repetition(反復): 一貫させ、利用者が画面を学べるようにする。混乱が減る。例: 向きや位置がばらばらのカードを一つの型にそろえる。
- Alignment(整列): 要素を組にし、リズムを作り、秩序をもたらす。揃えると見えない軸ができ、斜めに置いても秩序が残る。
- Proximity(近接): 近いものは関係があるように見える。見出しと本文、ボタン同士、セールの文言をそれぞれ組にする。

## UI スキルへの示唆【推論】

- 決定の順番を固定する: 利用者の意図 → 表示する内容 → 内容の端の場合 → 慣習に沿った配置 → 対比・反復・整列・近接 → 色を減らす・書体をそろえる → 控えめにする(影、線、角) → 意図した一点の個性。
- 各決定には、動画のような具体的な理由を一文で付ける(「〜したいので〜にした」)。理由は利用者の意図・内容・慣習・検査できる基準のどれかに結びつける。
- 批評はチェックの観点として使える: 次に何をすべきか伝わるか、現在地が分かるか、コントラスト、44px、アイコンの統一、状態の見分け、ボタンの文言の具体性、安心させる一言。
